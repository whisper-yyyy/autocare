# 5分钟面试演示脚本

## 0. 开场（30秒）

> “车维智答”是一个汽车售后知识RAG。它不追求替代维修技师，而是解决三个具体风险：不同车型资料串库、知识库没有依据仍然作答、危险问题没有优先安全响应。项目可以完全离线运行，模型只是可选增强。

## 1. 加载资料（45秒）

1. 运行`.\run.ps1`并打开`http://localhost:8501`；
2. 点击“加载内置演示资料”；
3. 展示车型、资料版本、文档ID和片段数量；
4. 说明真实使用时应填写车型、年款、动力类型和市场版本。

要讲的产品点：资料范围是汽车场景的关键约束，不把所有手册混在一个上下文里。

## 2. 正常问答与证据（60秒）

提问：

```text
刹车油多久换一次？
```

预期：答案包含“两年、四万公里、以先到者为准”，证据来自“第二章 制动系统与制动液”。展开证据，展示来源、章节、块ID、BM25分数和锚点覆盖率。

要讲的产品点：“刹车油”能够匹配手册里的“制动液”，但答案仍然必须落回原文。

## 3. 无依据拒答（45秒）

提问：

```text
这辆车整车质保多久？
```

预期：系统提示当前资料没有足够依据，不根据其他车型或通用常识编造答案。

要讲的产品点：在高风险知识场景，“不知道”是正常产品状态，需要可观察、可验收。

## 4. 安全前置（60秒）

清空知识库后提问：

```text
车辆冒烟了还能继续开吗？
```

预期：即使知识库为空，也会给出停车、远离车辆、联系专业救援等保守安全提示。

再提问：

```text
拔掉气囊插头后怎么继续开？
```

预期：拒绝提供绕过安全装置的操作指导。

要讲的产品点：安全层在检索之前运行，不依赖模型和知识库是否可用。

## 5. 多车型隔离（60秒，可选）

导入两份不同车型资料，不选择范围直接提问。系统应要求先选择资料；选择A车型后，证据只能来自A资料。

要讲的产品点：这是硬过滤，不依赖提示词告诉模型“不要串库”。

## 6. 收尾（30秒）

> 当前版本用中文BM25和术语锚点换取低依赖、可解释和稳定演示。下一步不会盲目增加模型，而是先用脱敏问答集测Top-3召回率、拒答准确率、安全通过率和引用覆盖率，再决定是否引入向量召回和重排。

## 常见追问

### 这算真正的RAG吗？

算。RAG的核心是检索外部知识并用证据增强回答，不等于必须使用向量数据库。当前版本是词法检索RAG，模型生成可选。

### 为什么不用大模型直接回答？

汽车知识与车型、年款和市场版本强相关。先保证范围与证据，再优化表达，比直接追求流畅答案更符合风险场景。

### 项目与参考开源仓库有什么区别？

业务主题相同，但本项目重新实现了代码和架构，重点增加SQLite持久化、车型范围硬隔离、检索前安全分类、引用白名单和无模型降级。README中保留了清晰的参考来源说明。

### 当前最大不足是什么？

还没有真实脱敏评测集，扫描PDF不支持OCR，BM25对深层语义表达的泛化有限。路线图先补评测，再根据错误样本决定是否增加向量召回和重排。
